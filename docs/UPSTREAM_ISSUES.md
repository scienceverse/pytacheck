# Upstream issues found while porting

pytacheck reproduces metacheck's behaviour, including its bugs (see
[PORTING.md](PORTING.md)). This page collects problems found in metacheck (`dev` plus
pull request [#423](https://github.com/scienceverse/metacheck/pull/423), bibr export
schema 12.0, as pinned in `parity/UPSTREAM.toml`) so they can be reported upstream, and
records the few places where pytacheck deliberately differs.

## Deliberate differences

| # | metacheck behaviour | pytacheck | why |
|---|---|---|---|
| D1 | Reads bibr export schema 12.x natively (PR #423: a JSON file with a root `schema_version` goes to `.read_bibr12()`, other versions such as 11.x stop; files without one read as before), but its defaults keep the older format: `read()` of Grobid TEI and `grobid_to_bibr()` give the older conversion (`schema_version = NULL`), and `paper_write()` saves the paper object unless `schema_version = "12.0"`. | Reads the same way. Defaults produce 12.x: `read()` of TEI (keyword-only `schema_version="12.0"`, an argument metacheck's `read()` lacks) and `grobid_to_bibr(schema_version="12.0")` give a 12.x paper or file, and so do `convert()` of XML, `convert(method="grobid")`, `convert_grobid(save_path=None)` and the CLI. `paper_write()`'s default `schema_version="auto"` writes a 12.x paper as a 12.0 file (byte for byte what `"12.0"` writes, apart from D4) and an older paper as before. A paper read from a later 12.x (12.1) is refused under `"auto"`, as under `"12.0"`. `schema_version=None` gives metacheck's behaviour everywhere. Parity cases run the Python side with metacheck's defaults (`METACHECK_DEFAULTS` in `parity/cases.py`), and cases that want 12.0 pass it on both sides. | bibr export schema 12.0 is the schema pytacheck targets. A paper read from bibr's export, or converted from Grobid, is a 12.x paper, and saving it writes a 12.0 file. |
| D2 | `convert(method = "bibr")` calls `do.call(convert_bibr, valid_args)` with the argument *names*, so it always fails ("second argument must be a list"). | Passes the argument values, so conversion through a bibr server works. | A documented method that can never succeed; not parity-testable without a server. |
| D3 | `doi_resolves()` crashes ("argument is of length zero") on a connection failure, because `.batch_query()` returns `NULL` rather than an error object; its `timeout` argument is never used. | Returns `NA` (the documented result) and honours `timeout`. | Documented intent. |
| D4 | 12.0 files written by `paper_write(schema_version = "12.0")` or `grobid_to_bibr(schema_version = "12.0")` name metacheck (and its version) as `extraction.converter`. | Names pytacheck: `{"name": "pytacheck", "version": <pytacheck version>, "build_sha": null}`. Nothing else in the file differs; the parity cases mask the converter (and `completed_at` when the TEI has no `<application when>`, where it is the time of conversion). | The converter records the software that wrote the file. |
| D5 | Messages that name R: `schema_version must be NULL or "12.0"`; `METACHECK_SOURCE_SHA256_UNAVAILABLE` says "SHA-256 needs R >= 4.5 or the digest package." | `schema_version must be "auto", None or "12.0"` (`paper_write()`) and `schema_version must be None or "12.0"` (`read()`, `grobid_to_bibr()`); the SHA-256 warning says "The source file could not be read.", the only way it happens in Python. | The messages name Python's values and causes. |
| D6 | `read()` of a directory or of several files fails entirely when one file cannot be read (U21), for example a bibr 11.x export next to 12.x ones. | Logs the unreadable file and skips it; the others are read. Parity case `read.dir.v11_and_v12` is a `known_divergence`. | One bad file should not lose a corpus. This is pytacheck's existing `read()` behaviour. |

## Bugs reproduced faithfully

| # | where | issue |
|---|---|---|
| U1 | `DESCRIPTION` | `Depends: R (>= 4.3.0)`, but the package needs R ≥ 4.5 (`tools::md5sum(bytes =)` in `paper()`, R ≥ 4.5.0) and `sort_by()` (R ≥ 4.4.0) in `module_list()`. |
| U2 | `inst/plumber/endpoints/paper.R` `/paper/search` | forwards the documented `section` parameter to `text_search()`, which has no such argument, so any request using it fails with "unused argument". pytacheck's API returns the same 500. |
| U3 | `format_ref()` / R `bibentry` | the author string of hand-written references (e.g. in `marginal`) is re-parsed by R's bibentry formatter into "…Hartgerink &amp;, J. CH"; pytacheck stores the HTML R produces. |
| U4 | `stats()` (R/stats.R) | `tryCatch(warning = )` drops all of a sentence's statcheck results on its first warning, so an unrelated unparseable p-value (`p = .05-.10`) removes valid results; any statcheck error also drops the sentence. Unknown arguments in `...` make every call error, and the error is swallowed, so `stats()` returns an empty table. A character vector input errors ("argument is of length zero"). |
| U5 | statcheck 1.5.0 | Q-test subtype detection looks for a lowercase `b` then `w` in the test name (`Q-Between(2)` → Qw). `RGX_P_NS` is case-insensitive while `[^a-z]` is not, which misaligns p-values across results via `data.frame()` recycling. `if (NA)` / length-2 `if()` errors (df = 0, r = ±1.00, `t(20) = (2.1`) abort the whole call. |
| U6 | `module_report()` (R/report.R) | the greedy `\\s*\\(.*email\\{.+\\})` gsub cuts a single `@author` line naming two authors down to the first name (`stat_p_exact`). |
| U7 | `report_qmd()` | a module `summary_text` with several elements errors in R ≥ 4.3 (`'length = 2' in coercion to 'logical(1)'`), failing the whole report. |
| U8 | `link(type = "doi")` | turns `NA` into a link to `https://doi.org/NA`. |
| U9 | `json_expand()` | a `_row` key holding nested objects with NA cells is mangled by jsonlite's `rn[is.na(rn)] <- …` replacement through a logical matrix; not reproduced. |
| U10 | `extract_tests()` | fails on paper lists and on some papers whose sentences mix anchors with unknown statistic names; `extract_eq()` errors on `NA` paper ids and orders `grp_id` inconsistently. |
| U11 | `test_paper()` | paper ids differ on every run even after `set.seed()`, so goldens built from test papers compare everything except `paper_id`. |
| U12 | `doi_lookup()`, `datacite_doi()`, `openalex_doi()` (R/doi.R, R/db-crossref.R) | `return()` inside `tryCatch()` exits the whole function, so one HTTP error (e.g. a 404 for one unknown DOI) makes `doi_lookup()`/`datacite_doi()` return `NULL` and `openalex_doi()` return only that DOI's error. `bibdata[[i]] <- NULL` in the error handler deletes list elements, shifting later rows. An author without family/given name puts `character(0)` in the author string; `bind_rows()` type conflicts crash on numeric CSL/DataCite fields. |
| U13 | `crossref_doi()`, `.crossref_parse_item()`, `crossref_query()`, `openalex_query()` | The `inherits(resp, "error")` branch is dead, so connection failures give "`resp` must be an HTTP response object" and `add_bib_match()` never counts them. A JSON `null` in a selected field makes `data.frame()` fail ("differing number of rows: 1, 0"). `crossref_query()` on data frames deparses list cells, joins fields with a literal backslash-n, and fails without author/container columns. `openalex_query()` sorts `relevance_score` as text; its `select` argument is ignored. |
| U14 | `pubpeer_comments()`, `check_orcid()`, `.openalex_add_abstract()`, `regcheck_start_local()` | `auto_unbox` sends a single DOI as a JSON string, not an array; fails when no feedback has an id. `check_orcid(NA)` and ORCiDs with `X` in the first 15 characters error instead of returning `FALSE`. An empty inverted index fails the abstract rebuild. `method = "docker"` ignores `port`. |
| U15 | `rw_update()`, `data-raw/retractionwatch.R` | Rows whose DOI is `""` are kept, so joins on `doi` match every reference without a DOI (`ref_retraction` filters these first; other joins do not). |
| U16 | `.xml_read_grobid()` (R/import-grobid.R) | The number-before-operator clean-up runs on raw XML, so the `<` of closing tags counts as an operator (`Fig. 1</ref>` → `Fig.1</ref>`). The omega fix `"\u03C\\s*p\\s*2"` is read as `<` (U+003C), so it rewrites `<p2` and never fixes omega. `\\bd\\g+z\\b` uses `\g`, which TRE reads as a literal `g`. |
| U17 | `.grobid_to_bibr()`, `.tei_text()`, `.tei_bib()`, `.xml2bib()`, `.process_full_text()` | Whole papers fail to load when a table has no rows (with exactly 2 tables it silently duplicates/drops contents instead), a `biblStruct` lacks a raw reference note, a page `biblScope` has only `from` or `to`, a URL ref has empty text (`gsub("", …)`), or a reference has no text rows. Nested body divs duplicate paragraphs; back matter outside an inner `div` is dropped. The paper DOI falls back to the first reference DOI. Figure/table first-div detection only fires when exactly one sentence qualifies and depends on tibble vs data frame input; NA section types give figure rows with NA `section_id`. |
| U18 | `read()`, `convert()`, `papers_available()`, `papers_load()` | `read()` of several files errors as soon as one fails to parse. `convert()` of XML still needs `online()` and the server list although no server is used. `papers_available()` errors for a repository without `.rds` assets and `papers_load()` then fails with "argument is of length zero". |
| U19 | `llm()` (R/llm.R) | Unstructured calls error whenever some requests succeed and others fail (`bind_rows()` cannot combine `ellmer_output` with `NA`). `isTRUE(answer_df$error)` never warns for multi-row failures. Answers are joined back on the *unsanitised* text, so inputs changed by `.llm_sanitise_text()` get `NA`. Numeric text makes every call and then fails at the join. `NA` texts are sent as the string `"NA"`. |
| U20 | `llm_cache()`, `llm_timeout()`, `.onLoad()` | Cache keys hash `serialize()` output, whose header records the R version, so upgrading R invalidates the cache. `llm_timeout()` only bounds native Ollama requests (ellmer uses 300 s). `GITHUB_PAT` still selects the defunct `github` provider as default. HTTP error messages are wrapped at the console width, so stored error text depends on the terminal. |
| U21 | `read()` (R/import-read.R) | Extends U18. `read()` returns `NULL` for a file it cannot read, and `paperlist()` then rejects the `NULL` ("The arguments must be paper objects or lists of paper objects", and prints the list). So a directory or list with one bad file cannot be read at all, and since PR #423 any bibr 11.x export in a folder triggers this. A single unreadable file also reports that message instead of the real error. pytacheck raises the real error for a single file, and skips the file in a directory (D6). |
| U22 | `paper_write(schema_version = "12.0")` (R/paper.R) | jsonlite's `digits = NA` writes doubles with 15 significant digits, so rewriting a bibr export changes values (`extraction.diagnostics` `citation_linking` 0.9411764705882353 → 0.941176470588235). The PR says a rewrite "changes nothing but converter", which only holds within `expect_equal()` tolerance. pytacheck writes the same bytes. |
| U23 | `ref_pubpeer` (inst/modules/ref_pubpeer.R) | Crashes with "`y` must be a data frame, not NULL" when PubPeer answers with a non-200 status: `pubpeer_comments()` returns `NULL` and `inner_join(bib, NULL)` fails. Not specific to 12.x. |
| U24 | `.read_bibr12()` (R/import-bibr12.R) | Malformed 12.x input stops with opaque base-R errors: a scalar table row ("subscript out of bounds"), a scalar `source`, `extraction` or `producer` ("$ operator is invalid for atomic vectors"), `[null]` or a nested array in a scalar field ("replacement has n rows, data has m", recycled when the length divides), and a `df` array of other than one element ("missing value where TRUE/FALSE needed", "'length = n' in coercion to 'logical(1)'"). Any `df` not already in parentheses is wrapped, so `""` becomes `"()"`. pytacheck stops with the same messages in the same order. |
| U25 | `.read_bibr()`, `.read_bibr12()` | R's `$` matches a unique prefix: in a file with no `bib` key, `data$bib` reads the `bib_match` rows as the `bib` table (and `data$info` would match `info_match`); `metadata`, `source`, `extraction`, `producer` and the root `schema_version` are looked up the same way. pytacheck reproduces the prefix matching, except that R turns `bib_match`'s list cells (authors) into deparsed strings in `bib`, which is not emulated. |
| U26 | `.bibr12_utc()` (R/import-grobid-bibr12.R) | Years below 1000 lose their zero padding (`0026-05-27T08:58+0000` → `26-05-27T08:58:00Z`; an offset before year 0 gives `-1-12-31T23:00:30Z`), which is not a valid 12.0 date-time. It is not vectorised: a vector input fails with "the condition has length > 1". |
| U27 | `.grobid_to_bibr12()` (R/import-grobid-bibr12.R) | Body text rows keep runs of spaces (as in the older conversion), while captions, footnotes and the abstract are squished. U16's number-before-operator clean-up now also reaches 12.0 xref contents and captions (`Fig. 3</ref>` → `Fig.3`, `Figure 4</ref>` → `Figure4`, `== 3` → `==3`). |
| U28 | `.grobid_to_bibr12()` URLs, sentences and ORCIDs | A URL's link text is replaced with a fixed `gsub()` over every text row (body, references, captions, footnotes), one URL after another, so a short link text such as `osf` is also replaced inside other links and inside earlier replacements (`https://https://osf.io/q2.io/q2`). A `<ref type="url">` without a target turns every row that prints its link text into `NA`. With Grobid's sentence segmentation (`<s>`), the re-parse `read_xml(as.character(xml))` indents under `xml:space="preserve"`, so each paragraph stays one row with 3-space runs between sentences. An author with several ORCIDs keeps the last one (greedy `.*(`). A `<REF>` tag is found because the HTML re-parse lowercases tag names. |
| U29 | `grobid_to_bibr(save_path, schema_version = "12.0")` | The saved file is named after the TEI (`published.pdf.tei.json`), while `paper_id` and `source.file_name` follow the PDF (`published`, `published.pdf`). |
| U30 | `ref_accuracy` (inst/modules/ref_accuracy.R) | A paper without `bib_match` rows (every Grobid conversion, for example) gets the traffic light `"error"`, which is not one of metacheck's lights (`na`, `fail`, `info`, `green`, `yellow`, `red`). pytacheck returns the same light; `pack check` flags it as invalid. |
